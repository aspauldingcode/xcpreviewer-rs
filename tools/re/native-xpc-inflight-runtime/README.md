# In-flight native XPC reply controls

Run `python3 tools/re/native-xpc-inflight-runtime/run.py --output NEW_DIRECTORY`, then `python3 tools/re/native-xpc-inflight-runtime/verify.py NEW_DIRECTORY`. This compiles original Objective-C code and executes public libxpc in owned processes. It does not construct a private Canvas connection. The anonymous listener/client and original marker messages are in one process; target/reply delivery uses an explicitly configured serial queue. Compiler deadline is 30 seconds; children have an internal six-second alarm and external eight-second deadline. The shared controller lock covers native runs.

Modes are normal dictionary reply, cancellation while that reply callback is blocked, and cancellation while the peer still holds an unsent reply. Each reply block captures an original FD-owning object; its caller reference is released after submission. Native deinit/close and callback ordering are observed. Structured events stream immediately and are also included in the final record. `mutations.py NEW_DIRECTORY` corrupts eight semantic evidence fields; it does not execute native code.

The loaded libxpc path/UUID and accepted peer PID are checked. The anonymous client's server-PID query returns zero in the captured controls; it is not treated as verified remote identity. Earlier equality assertions incorrectly required the process PID and caused two owned-process aborts; exact failures are retained. Do not repeat that failed assumption.
