# Local preview viewer

From the repository root, run `python3 tools/re/browser-preview/serve.py`, then open the printed loopback URL. Requires Python 3, Rust, and the installed `wasm32-wasip1` target. The offline build uses the locked workspace dependencies. `--sample /absolute/path/capture.bplist` supplies an explicitly chosen local capture for the Open sample button, including updated captures written atomically at that path. A prebuilt owned executable can be supplied with `--wasm /absolute/path/canvas-frame.wasm`; `--port` selects a fixed local port.

Choose **Open sample** or open a captured RenderPayload binary plist. Files are read inside the browser and are not uploaded. Select a region using its outline or list entry, then adjust zoom. The server exposes only the seven owned assets and accepts no file uploads. The worker has a ten-second deadline, a 256 MiB build-time linear-memory ceiling, bounded input/output, and exactly five stdin/stdout WASI imports. Unknown imports fail explicitly.

The Rust decoder, bitmap conversion and point-space geometry reuse the qualified reconstruction. The display packet (`XCPV` version 1), file bounds, zoom, region ordering, selection and error presentation are original UI policy. Accessibility blobs remain opaque; the viewer shows regions without interpreting those blobs. Unsupported pixel formats fail explicitly. Browser color conversion and alpha rounding are separate from native bitmap decoding; the opaque sample has byte-exact actual Canvas readback evidence.

This surface displays existing bitmap captures. It does not compile SwiftUI, invoke providers, render arbitrary native views, dispatch Apple interactions, or establish native Canvas parity. Both reconstruction milestones remain incomplete. Open `/?verify=1` for page-owned Canvas readback hash attributes used by the recorded manual browser verification.

For ordinary SwiftUI source, the separate [Mac capture tool](../swiftui-preview/README.md) compiles an explicit view factory with Apple’s public renderer. Feed its output through `--sample` or the file picker. This does not add project/provider discovery, browser-side Swift compilation or native Canvas lifecycle parity.

The [source watcher](../swiftui-preview/README.md#recapture-after-source-edits) can recapture a single Swift file after edits while preserving the last good frame. Enable **Follow sample** to display published captures automatically, or choose **Open sample** for a one-time load.

Follow sample is off by default. When enabled it fetches the selected loopback sample once per second after the preceding read finishes, hashes its bytes and runs the WASM decoder only for changed bytes. Each fetch has a five-second deadline and the existing 64 MiB sample limit. Failed reads/decodes retain the last displayed frame; a later changed valid capture restores it. Turning following off, opening a file or choosing Open sample stops polling and cancels pending display work. Unchanged frames retain zoom/selection; new frames reset region selection. Polling stops when the page is left. The server route remains the explicitly selected local file; arbitrary filesystem paths are not exposed.

This polling and content-hash policy is original reconstruction behavior. It does not reproduce native Canvas refresh scheduling, provider/state migration or interaction forwarding. A continuously changing source can supersede an in-flight display; newest accepted request wins. The worker retains its ten-second deadline. Browser timers may be throttled in background tabs.
