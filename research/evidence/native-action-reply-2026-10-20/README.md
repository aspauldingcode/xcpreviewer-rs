# Native local action reply and capture accounting

Four independently executed owned BaseBoard BSAction cases produced exactly one callback and one captured-object deallocation each: success; owned NSError domain Owned.ActionError/code17; native timeout BSActionErrorDomain/code2; explicit invalidation code5. The action starts valid/respondable and ends invalid/nonrespondable. Runtime Objective-C signatures are checked before NSInvocation. The handler captures an owned object; its atomic deallocation counter is read after action release and queue barriers. No external XPC action is sent. No Xcode workspace is opened, swizzled or terminated.

The bounded oracle waits at most500ms for callback, then invalidates/drains, observes150ms and drains again. This proves measured local callback/capture accounting within that window. It does not establish unbounded no-later-effect, remote target settlement, all native allocation release, IOSurface/Mach/GPU retirement or Canvas transport parity. Child exit alone is not settlement evidence.

A duplicate native sendResponse trapped the owned process. Initial and diagnostic failures remain in ignored raw provenance. The original Rust sequential gate returns AlreadyClosed instead of trapping, preserves error descriptors, and admits one outcome. Caller-reported expiration/invalidation create local failures; the adapter creates no timers, dispatch queues, native cancellation or transport. Tests use a frozen native outcome fixture, all27 serial three-event sequences, and drop accounting for accepted and rejected owned values; these do not prove native concurrent scheduling. All76 canvas-core tests pass. Seven mutated native receipts and three corrupted mapped containers are rejected.
