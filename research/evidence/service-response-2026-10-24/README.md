## Portable response path

select_service_response_with takes a caller-supplied connection-availability observation, nullable payload/error and explicit error projection. It skips all work when unavailable, preserves payload precedence, and returns no response for missing or unprojectable error. It never invents EmptyReply or an empty response for an absent outbound outcome. The boolean is a portable input, not an implementation or proof of native weak-reference lifetime.

send_service_response_with composes that selection with the existing ServicePropertyList coder and caller's send function. It leaves the reply dictionary unchanged and skips send when no response is selected. Otherwise it writes data while preserving unrelated entries, then returns Some of the caller's send result, including failure. Stored payload data bypasses serialization. Projected NSError values use the exact previously recovered value dictionary; Foundation-compatible serialization remains caller-supplied, including XML/coercion/arbitrary native object behavior outside this Rust Value profile.

The portable coder always writes one data entry, so this composition cannot take the native count-zero error fallback. Serialization failure writes zero-byte data and still calls send, matching the earlier native property-list controls' nonzero XPC count. Alternate native coders/count-zero outcomes retain the separately exposed fallback helper; this implementation does not substitute value-map length for actual XPC count.
