# Owned observer-context destructor reentry during native invalidation

Static expansion is paused. Two fresh owned-process executions each passed fifteen normal native observer controls against the pinned shipped PreviewsFoundationHost image. The original thirteen controls regress, including 100 sampled concurrent rounds in each run. Two new controls exercise **our Probe context's deinit**, not a newly recovered Apple Canvas destructor:

- **invalidate-deinit-reentry:** an observer runs, its context begins deinitialization inside the outer native invalidate interval, closes its owned FD and recursively calls invalidate on the same still-owned handle. Nested invalidation returns; deinit continues; outer invalidation returns. A later repeated invalidation produces no new observer callback.
- **invalidate-deinit-add:** the deinitializing context registers another observer against that already invalidated handle. The late callback runs synchronously inside add, before registration returns with no token. Its caller reference is released and its own context/FD cleans up before deinit and the outer invalidation interval finish. Repeated invalidation produces no additional callback.

The caller continues owning the native handle throughout; no use of a deinitializing handle as self is attempted. `destructionReentry` is cleared before the nested operation, deliberately bounding reentry to one level. The original recorder has a strong Probe local; precise placement relative to the ABI return instruction is not independently traced. Claims are bounded by logged callback/deinit/nested API/outer API intervals, not an inferred internal unlock instruction or universal destructor safety.

These positive invalidation-time controls differ from the **historical** cancellation-time destructor-reentry recursive os_unfair_lock termination. That negative case was not rerun, and its result is not generalized to these paths. No new native failure, crash or deadline occurred in this checkpoint. Existing compiler weak-mutability/Swift 6 Sendable warnings are retained; no strict Swift 6 claim follows.

The final reader matches create/deinit FD identity by **context name**, allowing non-overlapping numeric reuse; a global integer is not treated as persistent resource identity.
