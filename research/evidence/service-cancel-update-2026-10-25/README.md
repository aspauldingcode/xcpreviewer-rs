# Lossless UInt64 cancel-update identity

The portable service envelope now supports cancelUpdate with required pid:Int32, contentIdentifier:String and updateSeed:UInt64. All three fields are required and payload decode errors propagate. The outer optional message identifier remains a separate payload field. This adapter constructs/decodes identity values; it neither sends a cancellation nor matches or settles a native update. PreviewUpdateSeed is unsigned and distinct from the existing signed scene-timing seed type.

## Shipped-code recovery

Current PreviewsMessagingHost identity matches preceding seals.1228 selected instruction bytes independently match LLVM output. Reflection and bounded raw-key evaluation recover pid/contentIdentifier/updateSeed. The decoder performs three required unarchiveValue calls in that order and propagates errors. Its ContentIdentifier wrapper uses a String raw representation with a copy-only constructor. Exact symbol-table entries identify PreviewUpdateSeed's UInt64 property-list getter/initializer, whose folded code copies all64 bits. LLVM aliases at shared addresses are not treated as type authority. The cancelUpdate outer MessageType tag8 selects the payload decoder, and Content tag6 selects its serializer followed by the common optional identifier tail. These internal tags are not numeric wire values. No private function is invoked through a guessed ABI.

## Unsigned plist gap and implementation

The existing Value tree could only retain signed Int64 integer payloads. Foundation encodes UInt64 values above Int64.max with a16-byte positive plist integer, so merely adding a signed cancellation seed would truncate or reject valid identities. Value now has Unsigned(u64). The bounded reader recognizes16-byte integer objects only when the upper eight bytes are zero and the lower bytes fit UInt64; values at or below Int64.max canonicalize to Integer. Nonzero upper halves, negative128-bit integers and larger integer widths remain unsupported. Existing8-byte signed-negative behavior stays intact. The writer uses the Foundation-compatible16-byte positive representation above Int64.max, includes all17 object bytes in its output-size budget and canonicalizes smaller Unsigned values to the existing Integer representation.

This adds a public Rust enum variant: callers with exhaustive Value matches must handle Unsigned. It does not claim generic signed128-bit support, preservation of original integer width or NSNumber class identity. Existing non-integer node/depth/byte/reference limits remain in force. Other modules retain their scoped signed/typed profiles; the new variant does not silently widen every domain-specific numeric field.

CancelUpdatePayload retains a full u64 seed and emits a canonical Integer or Unsigned as needed. PID uses the existing measured primitive Int32 compatibility helper. UInt64 seed conversion accepts explicit unsigned values, nonnegative signed values, Bool and exactly integral finite real values below2^64; negative/fractional/nonfinite values and Double(2^64) reject. ContentIdentifier retains its exact String, including empty strings. No ID generation, scene-seed reinterpretation, cancellation controller or completion guarantee is added.
