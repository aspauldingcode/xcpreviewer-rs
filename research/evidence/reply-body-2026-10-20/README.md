# Portable observed XPC v5 body codec accepted by native receiver

Original xpc_wire.rs now decodes and canonically encodes the independently observed attachment-free primitive/container subset of libxpc version5 bodies. A portable reencode-xpc-body CLI validates a bounded extracted body and writes a new canonical body without native calls. The library remains std-only and forbids unsafe code. No Mach header, message rights, OOL storage or unobserved tag is synthesized. Cross-host/WASM execution is not newly claimed by this native-host build.

Two original native inputs put a public xpc_dictionary directly into an owned BSActionResponse settings slot, avoiding opaque Foundation secure archives for the selected payload. Native callback xpc_equal independently verifies booleans, signed/unsigned integers including extrema, raw data with zero/255, strings, nested array, and holdout UTF-8 snowman plus empty dictionary. An independent Python decoder validates the full native response tree, including BSActionResponse/BSSettings class wrappers and the actual two-element direct-XPC settings entry. A manually specified Rust expected tree checks both native inputs. No raw native body or Apple binary/decompilation is published; input/output bodies remain local. Public tests contain original typed expectations and a small original fixture, with explicit environment-driven native conformance tests rather than quietly shipping a private packet dump.

Current-source Rust CLI canonicalizes328- and352-byte native bodies. Its output uses a different dictionary order. Only in a newly compiled owned helper, an original dylib substitutes these candidate bytes below native serialization while preserving the original owned Mach header/right. Native receiver accepts both replies and returns exactly the expected complete typed values on the owned queue. Candidate bytes equal every byte observed before kernel send and after successful native receive; native originals are similarly compared. All1,360 body bytes across original/candidate pairs agree at their respective sender/receiver boundaries; native versus canonical ordering is compared semantically, never falsely claimed byte-identical. Fresh locked replay rebuilds the native tools and current portable CLI, supplies the fresh native corpus to Rust tests, then repeats native acceptance and the independent Python comparison. Sixteen corrupted bodies reject in the Python verifier; Rust tests additionally cover truncations, padding, version, tag, duplicate keys, UTF-8, integer extremes, depth and unsupported attachment tags. All95 core tests pass; five final targeted tests pass with actual native corpus supplied.

Observed framing is CPX@ followed by little-endian uint32 version5. Each value begins a little-endian uint32 tag. Supported tags are0x2000 bool (uint32 0/1),0x3000 int64,0x4000 uint64,0x8000 data (uint32 byte length),0x9000 UTF-8 string (uint32 byte length including terminating NUL),0xe000 array and0xf000 dictionary. Keys are NUL-terminated UTF-8 without a value tag. Strings/data/keys align to four bytes. Container uint32 length counts content bytes after the length field, including uint32 element count. Values occupy exactly the declared content extent. The codec imposes64MiB,100,000 nodes and depth64 limits and rejects nonzero padding, duplicate keys, unknown tags and trailing bytes. These strict policies are original choices, not universal native malformed-input/coercion behavior. Only this version and seven measured tags are supported; floats, null, endpoints and other native types remain explicit gaps.

libxpc identity inherits the sealed prior route proof: UUIDc40fcae87a173d8287cb3da4802adef1, mapped ARM64 hashbe92683dd727339d21ad82f4d3624e97757c327a4387172fc1a7d4acef5417fc. Accepted native and candidate send/receive receipts independently resolve that actual UUID. REA reopened the exact image and closed; Ghidra reused its server. The CPX@ header literal exists in the pinned native image. Raw decompilation contains guessed prototypes/PIC boundary artifacts and is not promoted to a callable private ABI. Candidate private serializer symbols were not exported, so native controlled input/output provided the usable observation boundary instead.

A meaningful tracer failure was caught: adding a large stack replacement buffer made builtin return-address capture report the owned stack-probe call return. These receipts failed libxpc identity admission and remain local with source/disassembly. A thread-local replacement buffer fixes attribution; only fresh locked replay counts as final acceptance. The native receiver and payload outcome were never substituted by an owned model. No malformed body was fed to private native decoders. All compilers/native helpers/verifiers have bounded deadlines, and no user process, Xcode MCP/private bridge, workspace or system protection was changed. Both milestones remain open. Next: missing primitive/attachment descriptors and cross-process reply resource ownership, concrete workspace client proxy encoding, and correlated actual owned Canvas lifecycle/input. Portable endpoints and full native application compatibility remain unsupported.

Usage: cargo run --offline -p canvas-core --bin reencode-xpc-body -- INPUT OUTPUT. OUTPUT must be a new file. INPUT must already be an extracted supported XPC body, not an entire Mach packet.
