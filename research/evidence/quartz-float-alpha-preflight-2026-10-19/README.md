# Float32 alpha/profile counterpart: unexecuted preflight

This package implements an owned offscreen C probe and an independently written Python byte comparator. It contains no native measurements. The source has not been compiled or executed. Synthetic tests passing do not establish CoreGraphics support for this route, native acquisition, or an accepted numerical model. Both milestones remain open.

The preceding eight-bit premultiplied source experiment rejected the predicted nonlinear-to-linear primary identity in 9,540 bytes while the linear-source control matched all 49,152 bytes. This follow-up changes the source component depth to Float32 while keeping the 768 × 3 primary/alpha lattice, destination, profiles and geometry. It omits the unrelated opaque-gray route. This is a discriminating source-depth contrast, not a repeat of the eight-bit input or a fitted replacement lookup table.

`probe.c` constructs two Float32 premultiplied CGImages, nonlinear sRGB and linear sRGB, and copies each into a Float32 linear-sRGB bitmap. Source and destination stride is 12,352. The source allocation is 37,056 bytes; the destination is 49,152 bytes. Each row has 64 sentinel bytes after its 12,288 active bytes. Each destination has an additional 12,096 sentinel tail bytes. The program releases all created CoreGraphics/CoreFoundation objects and has a ten-second alarm. That alarm alone is not an approved subprocess ownership or cleanup mechanism.

`compare.py` independently constructs each little-endian Float32 provider field from the reciprocal-multiply expression bounded by the prior opaque normalization evidence. All provider bytes must match, including padding. It compares every destination byte against two separately named arrays: the independently generated identity prediction and the corresponding sealed eight-bit producer readback. The latter is a producer relation, not an accepted numerical golden. The anchored historical linear readback must equal the independent identity, and the historical nonlinear readback must differ. Nonlinear identity, historical equivalence, or neither are distinct possible observations. Any failed linear control prevents an informative source-depth interpretation. A difference cannot identify an internal datatype, processing order, or isolate all implementation changes associated with source depth.

The total comparison extent is 172,416 bytes: 74,112 provider and 98,304 destination bytes. Destination padding totals 384 bytes and tails total 24,192 bytes. Source sentinel padding totals another 384 bytes. Invalid provider bytes, output lengths/digests, metadata types, profiles, filenames, symlinks, destination padding/tail, and inconsistent producer PIDs reject. Active numerical mismatches are reported exactly, not silently admitted. The comparator always returns `native_acquisition_qualified:false` and `canvas_qualified:false`; it does not consume guard or compiler receipts and cannot serve as a native-acquisition admission gate.

Six synthetic test methods run normally and with Python optimization. They exercise independently written IEEE endpoint/interior bytes, both producer-relation branches, active mismatch retention, rehashed provider/padding/tail faults, metadata/profile/path/digest faults, PID mismatch, duplicate/non-finite JSON, truncated output, symlinks, and a nondiscriminating historical contrast. No C fixture is launched. Independent review found that the initial JSON parser accepted exponent overflow through an unused nested field. The corrected parser recursively rejects non-finite floats. `rejected-json-parser.py` reconstructs the original parser excerpt verbatim and retains the counterexample, explicitly as rejected tooling.

Bounded observed process cleanup and receipts must be verified. No compilation or native execution is approved by this preflight. No UI session, private bridge restart, product implementation, Apple binary or private dump is included.
