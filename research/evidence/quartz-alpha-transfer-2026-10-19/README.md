# Public Quartz premultiplied alpha and profile contrast

This owned offscreen public CGImage/CGContext experiment falsifies a numerical generalization from the earlier opaque byte-normalization oracle. It uses 8-bit premultiplied sources and Float32 destinations, with 256 alpha values crossed with three pure primaries. Two otherwise identical providers differ only in source sRGB versus linear-sRGB profile. A separate opaque-gray128 route checks that nonlinear-to-linear conversion is operational. No AppKit, SwiftUI, Canvas, workspace or private transport is involved.

All 175,680 provider/readback bytes are compared against independently frozen arrays, including 576 readback padding and 36,288 unused-tail bytes. All 28,224 provider bytes match exactly. The linear-source primary ramp matches its entire 49,152-byte prediction. The nonlinear-source primary ramp contradicts the same alpha-invariance prediction in 9,540 bytes: 4,770 alpha bytes and 4,770 designated-primary bytes, with other RGB components unchanged. The alternative that applies the transfer function directly to premultiplied components also fails. Therefore the strong primary numerical contract remains rejected normally and under optimization; measured values do not replace the prediction.

Its complete allocation was compared to both exact candidates, and all mismatches remain reported. Diagnostic field localization and a few sampled values are explicitly observations, not goldens or proof of an internal conversion order/datatype.
