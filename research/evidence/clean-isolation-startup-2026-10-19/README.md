# Isolated subprocess startup controls failed

This setup experiment tests an additional restrictive subprocess boundary for a future isolated implementation. No implementer, agent, product behavior, approved specification or target-derived input was launched/exported. This evidence cannot certify a clean room or model/tool isolation.

Three distinct candidate profiles were executed under the controller lock, each with seven finite commands and a5-second per-command timeout/45-second run budget. V1 allows selected system paths, owned original input and output only. V2 adds syscall/bootstrap and metadata startup allowances. V3 additionally allows executable mapping at selected system binary/library paths. All profiles retain default deny and bounded file-data allowances. No system profile, protection, permission or account was modified. Scripts and profiles are research artifacts, not approved clean implementation input.

For each candidate, the unsandboxed owned sentinel read returned exit0 and its exact23 bytes. Every sandboxed command returned-6(SIGABRT) with empty stdout/stderr, including the required allowed-input read and allowed-output write. All three inputs stayed intact; no output appeared. Therefore the denied-read/escape/mutation cases do NOT prove access enforcement: their positive startup controls failed in the same way. The harness continued the six planned sandbox cases despite positive failure; that is retained as a harness limitation, not admission evidence. There were no retries of an identical candidate and no further native attempt is scheduled.

A read-only look at matching cat/sh crash reports found SIGABRT/EXC_CRASH with termination namespace0x23, code2, flags582. Full crash reports are not included or published. This does not establish which requested sandbox operation caused startup to fail. The failed first candidate, both changed candidates and actual return codes are retained. Host source review informed the changed startup allowances; only source hashes are retained here, not Apple profile contents. No guessed Swift ABI or private Canvas operation is involved.

REA6.2.0 server/package identity matched. Opening the installed universal Mach-O sandbox-exec was rejected because the configured Ghidra provider could not enforce an architecture slice, Hopper was unavailable, and no alternate provider was admitted. The current session remained open:false. No binary was extracted, analyzed or published. File identity hashes independently bind the executed commands; they are not decompilation evidence.

The earlier Xcode acquisition remains valid at its own scope: successful build, finite appearance exports and exact close/fresh zero observation. This isolation experiment neither repeats nor supersedes it. The clean implementation prerequisite stays blocked pending an externally enforced fresh context/tool/filesystem boundary and independent behavior/provenance approval. A separate directory or exported spec alone is insufficient. Browser approval, typed private runtime and native target-operation settlement are separate gates. Both milestones remain open.
