# SwiftUI source to reconstructed browser preview — 2026-10-27

An original Mac producer now compiles an explicit ordinary SwiftUI view factory, captures one initial frame with public SwiftUI ImageRenderer and converts it through an owned sRGB premultiplied BGRA CoreGraphics bitmap. It emits the recovered RenderPayload schema with every bitmap field explicit. The existing Rust/WASM decoder and browser viewer display that capture. This adds a real source-to-frame workflow beyond the older declared primary-layer source subset. It does not reconstruct SwiftUI itself or establish native Canvas/provider parity. Both milestones remain incomplete.

Use `python3 tools/re/swiftui-preview/capture.py tools/re/swiftui-preview/Sample.swift --width 320 --height 200 --scale 2 --output /tmp/preview.bplist`. The tool README contains the copyable command. `python3 tools/re/browser-preview/serve.py --sample /tmp/preview.bplist` serves only the explicitly selected capture and owned viewer assets on loopback. Open sample loads it without a file-picker interaction. Recapture after a source edit and choose Open sample again. The selected sample path is read afresh, with a 64 MiB response bound. There are no uploads or external hosting services.

The producer uses one source file, SDK imports and an explicit zero-argument factory. A qualified factory name is supported. Source and generated-renderer hashes, compiler identity, deployment target, dimensions and payload/reference-image hashes are recorded. The executable targets macOS13; compatibility appearance and API availability follow that target and current native environment. Public ImageRenderer proposed size, scale, non-linear color mode and non-opaque rendering are explicit. The view receives the selected display scale and is clipped to the chosen point size. Native-provider discovery, PreviewProvider/#Preview registration, package/project build inference, device chrome, view hierarchy selection, interaction forwarding, state migration and hot reload remain separate. Platform-backed views may not be represented by ImageRenderer. Selectable regions are intentionally empty.

Three actual native captures cover a 640×400 text/rounded-shape view at scale 2, an asymmetric 64×48 opaque view from a qualified factory, and a 32×32 transparent view at scale 2. All1,040,384 complete premultiplied RGBA bytes agree with an independent Pillow decode and straight-to-premultiplied projection of the native PNG references. Orientation and transparent pixels are checked with complete literal raster controls in Rust. The actual shipped private RenderPayload decoder accepts all three; its canonical encoder reproduces every supplied field and pixel byte. Three native output values and three output property lists are destroyed with their native witnesses. A modified initial harness added an extra input-value destruction and trapped at an unlocated stage; that failed run is local, separately recorded and not acceptance evidence. Restoring the previously verified caller profile and adding stage receipts passes the complete decode/encode/output-destruction sequence. No final allocation reclamation is inferred.

Runtime export/image paths, native metadata 104/104/8, field offsets 0/80/88/96 and value-witness offsets are guarded. The public renderer/CoreGraphics producer is a separately observed original host adapter, not a claim that private Canvas snapshot, IOSurface or provider routines ran. Raw Apple instructions and initial failed originals remain local/ignored. REA6.2.0 expected package/path/catalog identity is aligned, target closed/provider null; unchanged provider limitations were not retried. Work remains serial under the exclusive controller.

Four CLI negative controls preserve both previous files: invalid source, owned runtime deadline, invalid factory syntax and over-limit dimensions. Bounds are original policy: 1 MiB source, 2,048 points per dimension, scales 1–4, 32 MiB bitmap, 64 MiB artifacts, 30-second compile and at most 8-second native render. Source/artifact reads are bounded. Timeouts cancel only the process group created by the invocation. Each output file replacement is atomic; the optional PNG and payload are not a transactional pair. Concurrent last-writer order, arbitrary source resource use, cross-host rendering determinism and native resource settlement are not guaranteed. Two compiler deadline failures and one initial 60-second Cargo deadline are preserved separately; Cargo checks were subsequently serialized with one job and pass within the same bounds. Context changes are recorded without attributing a single cause. No user/Xcode/simulator process was terminated.
