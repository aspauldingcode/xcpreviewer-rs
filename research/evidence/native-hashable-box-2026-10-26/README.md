# Native HashableBox control-state equality

This evidence executes shipped PreviewsFoundationHost `HashableBox<PlistValueBox>` creation, value getter, equality, hashValue and destruction in an owned ARM64 helper. MessagingHost supplies the original box values. No Xcode/simulator attach, UI action, private module import, app re-signing or protection change occurs.

The helper verifies loaded module paths and exact symbol offsets, native struct metadata, generic arguments/witness, field offsets, size/stride/alignment and destruction witness. The original assembly bridge adds a nonthrowing scalar-return entry forwarding x0-x3 and x20 self while saving/restoring x20/x21 and the frame. Generic metadata accessor and actual native conformance accessor are recovered independently. Conformance resolution uses an owned zeroed/aligned cache and verifies the returned witness's descriptor. HashableBox stores the original value plus cached AnyHashable projection. Native value getter copies survive source box destruction; output is destroyed through actual witnesses. All frameworks remain loaded until helper exit.

Selected native run: 57 wrapper constructions, 57 value reads, 57 hashValue reads, 3,249 ordered equality comparisons, 57 wrapper destruction returns, 57 initial box constructions, 114 direct underlying box destruction returns, and 57 encoded PropertyList destruction returns. Equal native pairs share hashValue within the helper process. Hash bits are randomized and never published or compared across processes. These are direct helper calls/normal returns, not heap-quiescence or global-settlement evidence.

Important observed boundary: Int64.max equals the binary64 value 2^63 in this Foundation-origin corpus, while UInt64 2^63 differs from that real. An initial broad Rust numeric projection failed pair26/27. Its failed test logs are retained. The portable implementation explicitly restricts Integer/Unsigned/Real magnitude to at most2^53. The source/runtime evidence does not yet explain all wider NSNumber conversion rules; no wider parity is claimed.

The original Rust HashablePlistBox retains original values and a cached equality key. Supported values: bounded numeric magnitude, finite Date, Bool, String, Data and recursive arrays/dictionaries. Bool is separate from numeric values; exact integral Real equals Integer within the domain; canonical Unicode String/key equality uses the existing qualified Unicode profile; arrays preserve order/multiplicity; dictionaries ignore encounter order. Null, nonfinite values, wider numeric values, canonical dictionary-key collisions and depth>64 are explicit portable restrictions, not inferred native rejections. No native generic type identity or native hash bits are reproduced.
