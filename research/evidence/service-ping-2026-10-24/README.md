# Ping service-message envelope subset

The portable service envelope now supports ping as well as forward, through ServiceEnvelope and ServiceContent. The existing ForwardServiceEnvelope API remains forward-only. Ping decoding requires root messageType="ping" and a payload dictionary; its identifier is the optional String under __unique_service_message_identifier inside payload. A ping has no other content-specific fields. Encoding builds an empty payload, optionally adds that identifier and writes the two root keys. Unknown decoded fields are omitted from canonical output. Value-only construction uses the existing shared process identifier allocator; neither construction nor decoding sends anything or establishes liveness, reply matching or completed work.

## Implementation and verification

ServiceEnvelope.decode uses the existing forward decoder for forward and a separate ping branch for the recovered unit content. Existing error variants and strict projected Value typing are preserved: missing root keys, non-dictionary payload and non-String present identifiers reject. Broader Foundation Any/NSNumber/optional bridging is outside this strict value profile. Other service message kinds remain explicitly unsupported. ServiceEnvelope.to_value emits canonical payload/identifier placement; it does not preserve unknown root or ping payload fields. new allocates only an identifier/value from the existing process-local sequence. No transport/controller or speculative cancellation behavior is added.

A public Foundation probe serializes four original ping dictionary controls to actual binary plists: no identifier, Unicode identifier, empty identifier plus extra data/root fields, and identifier-like fields in the wrong namespaces. These controls validate public binary serialization and full portable decoding/canonical projection. They are not native acceptance/canonicalization observations from the private ServiceMessage decoder. The schema authority is the shipped-code recovery above. Expected canonical dictionaries are authored independently in tests from that recovered contract.

All255 Rust tests pass offline. Three new focused tests compare complete fixture values/canonical output and binary round trips; cover required fields, wrong types, unsupported outer kinds, ignored unknown fields and namespace separation; preserve old forward wire output/error propagation; and exercise explicit ping/forward construction through the existing shared identifier sequence. Actual Node WASI preview1 executes these same controls with no filesystem preopens or inherited environment. This establishes portable value/codec behavior, not a browser Canvas or native ping transport. Disposable verify.py reruns source checks, the three changed tests, public plist generation, WASI build and actual execution. Full255-test output is retained separately. Native8s and compiler/test60s subprocess deadlines bound verification.
