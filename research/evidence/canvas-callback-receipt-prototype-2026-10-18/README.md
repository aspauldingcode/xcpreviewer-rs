# Owned callback receipt adapter proposal

This adds a Swift receipt writer, a diagnostic SwiftUI fixture proposal and an independent Python reader/comparator for future owned input controls. It modifies no reconstruction behavior or existing Xcode project. The UI fixture is not compiled, installed or executed. Its deliberately instrumented local file I/O is research telemetry, not a product preview pattern; native sandbox access and compilation remain unverified.

The proposed writer creates an exclusive pending file under an existing private operator-owned directory, writes complete canonical ASCII JSON plus newline, fsyncs the file, publishes through a no-overwrite hard link and removes the pending name. Failures retain pending data. It checks directory ownership/mode and refuses following the final directory/file symlink. These are source-level mechanisms, not measured native guarantees. File fsync without directory fsync does not establish crash-durable namespace publication, nor do these checks establish security against hostile ancestor-directory races.

The reader requires an externally supplied experiment nonce, parent-observed process PID and view UUID. It checks exact canonical bytes, filename identity, schema, event/count/sequence transcript, the complete bounded directory namespace, regular files and no pending/symlink entries. It supports only the declared appear0 then increment1/2/3 transcript. Additional appearances, view identities or gaps must stop admission; this is not a recovered general lifecycle rule. Seven test methods pass normally and under Python -O. A separate 19-case synthetic campaign admits one literal expected record and rejects 18 canonical-field, duplicate-key, padding/newline, non-ASCII and oversize mutants. All campaign bytes and hashes are retained. These are portable model controls, not native callback receipts.

Separate review conditionally approved one native compile and two owned CLI controls before the fixed 18:08 UTC cutoff. Dispatch reached the initial 65-second reserve guard too late and exited before creating a compile directory or launching any compiler/CLI job. The operator-transcribed exception and an explicit absence check are retained. No native writer result or compile error was observed. There was no retry, deadline extension, Xcode/UI session, input injection, process termination or bridge restart. The old native plan is closed.

The intended native positive control would compare four complete records against independent JSON expectations using the parent's observed child PID, rather than trusting a PID from output. Its duplicate control would require actual wait1, unchanged published appear0 bytes and retained conflicting increment1 pending bytes, then reject admission. These predictions remain unexecuted; do not promote them to filesystem measurements, Canvas input, release accounting, physical reclamation or private transport evidence.

Before any native input, the writer and UI fixture need a distinct independently reviewed compilation/feasibility step and native receipt controls. Change the scheduling/control method and review the new scope before fresh execution; do not replay or renew this expired plan. A later screenshot-bound calibration/input plan must require readiness receipts and per-view identity, retain failures, preserve source/runtime/transport distinctions and close its exact owned workspace. Both milestone acceptance contracts remain open.
