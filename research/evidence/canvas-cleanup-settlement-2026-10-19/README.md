# Cleanup requires operation settlement, not a timeout wrapper

This is an offline feasibility result for the native capture cleanup gate. The previous owned Xcode experiment missed its cleanup deadline; its later verified closure and original failure remain unchanged. The approved private bridge was running and responsive during this selection, but bridge availability does not provide UI operation cancellation or cleanup settlement.

A deterministic callback counterexample races an unresolved open against an injected timeout event. The wrapper reports timeout and observes zero windows; resolving the original open afterward produces a window. Promise.race does not itself establish that the losing operation has settled. The timeout and window are injected model events, not native UI observations or measurements of a real timer/provider.

The research coordinator tracks each registered owned operation until its promise settles. Cleanup returns pending without calling close or zero-window callbacks while an operation remains unresolved. After settlement, it attempts owned close once, then a fresh zero observation, checking both returned binding identities. Stop/deadline checks occur before registration and immediately before microtask dispatch. Snapshot mutation cannot erase pending work. Keeping the open/observe/finally sequence in one invocation removes model-turn boundaries only; it does not make a hung backend call bounded or cancellable.

Two prototype failures are retained. The first omitted the microtask dispatch recheck, allowing a stop between registration and invocation to miss dispatch. The separate verifier then found that observed expiry could reverse when the injected clock regressed. The corrected coordinator permanently latches expiry and invalid/nonfinite/throwing/regressing clocks. Clock faults deny timeliness but do not prevent owned cleanup or invalidate a separately successful close/zero observation. Cleanup exactly at the deadline is expired. Late cleanup can therefore be clean while cleanup_deadline_met remains false.

All25 deterministic cases pass. Both retained prototypes and six syntactically valid mutants fail their independently named cases: missing pending gate, missing dispatch recheck, late cleanup labeled timely, foreign close identity, coerced boolean zero and model results mislabeled native eligible. Independent Python admission requires the full case/variant matrix, source hashes and exact status types; seven altered report cases reject normally and under optimization. Node controls use five-second subprocess caps and no native UI APIs. The separate verifier independently reproduced the clock fault, reviewed the correction and replayed all25 cases, both prototypes and six mutants.

No native workspace was opened, sampled or closed during this wake. No current retained CUA registry/holder was recreated or modified. The coordinator is not installed in a native adapter and always reports native_eligible:false. Callback identities, registration completeness, clock source and callback receipts are trusted model inputs; the code does not authenticate a provider, prove unseen effects absent, bind an actual Xcode window or verify host cancellation/settlement. A zero response while an owned operation remains pending cannot remove the cleanup block.

Native multi-call UI execution remains blocked. Before another owned opening, require separately reviewed evidence that the chosen provider has bounded terminal operation settlement or cancellation with no later effect, plus a bounded close/fresh-zero path tied to the exact owned workspace. Single-call finally and timeout wrappers alone do not meet that prerequisite. No native Canvas protocol, interaction/state/transport, physical reclamation or milestone acceptance follows. Both milestones and the prior registry quarantine remain open.
