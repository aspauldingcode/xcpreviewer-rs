# Service process targets and control-message values

The portable service envelope now accepts connect, stop and kill as value messages with a distinct ProcessTarget codec. No process operation is performed. The shipped Service ProcessID has auditToken and pid cases, unlike the existing crash-listener ProcessIdentifier with pid/processName. Reusing that earlier type would produce the wrong wire schema.

## Recovered contract

Process-target dictionaries use discriminant, auditToken and pid. A PID value encodes discriminant="pid" and pid:Int32. An audit token encodes discriminant="auditToken", auditToken={val:[eight UInt32 words]} and a legacy pid field derived from the token. Token data is not an authenticated credential in this adapter: the code does not validate provenance, look up a task, signal a process or authorize an action. pid() performs only SDK-compatible value extraction from token word5 as signed pid_t.

Decoding first attempts the tagged representation. Any primary decoding error retries required legacy pid, including missing/wrong/unknown discriminant or malformed audit token. A valid tagged token wins over a conflicting input pid. A valid token without the auditToken discriminant does not bypass the legacy pid path. Invalid primary content without a valid fallback PID still fails. The original portable error categories identify the final PID failure; native NSError descriptions/identity are not reproduced.

The primitive compatibility profile accepts Bool, bounded integer and exactly integral finite real values for Int32/UInt32, matching the measured Foundation controls. Tokens require exactly eight words; no unbounded token-array allocation is introduced. Arbitrary Objective-C objects, additional Foundation bridging and future runtime behavior are excluded. Encoding canonicalizes numeric input to integers, writes both token and derived PID for the token case, preserves the outer optional identifier and drops unknown fields.

## Implementation and independent controls

service_process.rs provides ProcessTarget::{AuditToken,Pid}, borrowed decode_dictionary, decode, pid and canonical value output. It is separate from crash_listener.rs. ServiceEnvelope/ServiceContent now routes connect/stop/kill without changing ping, capabilities or forward behavior. The prior unsupported-stop test now uses still-unsupported launch, while new tests cover the implemented routes and their target payloads. No controller, process signalling or native session is added.

An owned public Swift helper serializes original dictionaries with Foundation, parses them back, applies actual Int32/[UInt32] dynamic casts, constructs only synthetic audit_token_t values and calls the compiler-declared public audit_token_to_pid. It composes the recovered precedence to generate complete original canonical records. Twenty-one controls cover signed PID bounds, Boolean/integral/fractional/overflow input, absent/unknown/wrong-type discriminants, valid conflicting token/PID, all-maximum token words, malformed token count/range, fallback success/failure and numeric token-array bridging. These are public cast/helper observations and source-guided composition, not actual execution of the private ProcessID decoder or service dispatcher. Synthetic token values are never submitted as credentials or sent to a target.

All261 Rust tests pass offline. Three new tests compare every complete native control's acceptance and successful canonical dictionary/round trip, verify all three envelope routes and outer identifier preservation, and check legacy-only fallback, fixed token length, signed high-bit PID extraction and portable nonfinite/null rejection. Actual Node WASI preview1 executes those controls without filesystem preopens or inherited environment. Dispatched action effects and browser/Canvas execution are outside these tests. Fresh disposable replay separately checks source, the changed three-test suite, typed semantic native plist values (preserving Bool/integer/real distinctions despite dictionary ordering), WASI build and actual execution. Full261-test output is retained separately. Native8s and compile/test60s deadlines bound checks.
