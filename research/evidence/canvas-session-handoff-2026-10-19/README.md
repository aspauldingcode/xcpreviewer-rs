# Closed-to-fresh caller handoff research

The existing native registry and closed per-session holder require deliberate admission before a new owned control. The previous native session was already closed and its seal/source/zero-workspace record verified. This wake changed no fixture, CUA state, registry, source or native session. Retained bridge status/window queries were read-only. Graph-loop and graph completed with no eligible candidates/execution; milestone backlog and current Canvas planner were inspected. Both milestones and native R1/R2 transport obligations remain open.

The offline admission helper receives the existing frozen registry, a closed prior holder, trusted closure record and new lease/config/app. It validates exact prior nonce/source/workspace and pending=false flags, a different new nonce/source at the same workspace, and retirable old wrapper methods. It creates no replacement registry. Old wrappers are retired before the caller can replace its global session slot: an older wrapper that dynamically reads that slot must not acquire the new context. Bind failure leaves old wrappers retired and returns no usable new holder.

The new holder captures private closed state, counters and fixed config. Frozen getters return copies of click attempts. Close suppresses results after pending AX or click awaits; click dispatch stays recorded and its effect remains unknown. It cannot undo a dispatch. Sixteen AX requests and two click API requests bound future opening-plus-selection use; these are policy limits, not evidence of native behavior. Current tests use mocks exclusively.

Executable counterexamples retain two prototype defects: exposed mutable closed/counter fields could be reset, and the first immutable revision could return click success after closure during an await. The separate verifier reproduced that latter gap. Corrected click wrapper now awaits the underlying result and rechecks closed/cutoff before returning; close-during-click and cutoff-during-click controls pass. Initial and pre-click-fix implementations remain.20case groups and before/after counterexamples pass; five syntactically valid mutants are rejected, including omitted retirement, missing post-await checks, boolean/zero confusion and ignored closed state.

Closure records, the supplied registry object identity, app/config/clock, source hash and filesystem alias/lease authenticity are trusted external prerequisites. Retirement covers dynamic method lookup through the pinned app object; independently saved function references are outside this revocation scope. These checks do not authenticate an arbitrary object, attest a process, prove UI atomicity or establish native resource release/completion. Existing source and registry-lifecycle quarantine are unchanged. The helper was not integrated natively; a fresh reviewed fixed-budget plan must retain the actual existing registry, bind a distinct nonce, use the already sealed explicit-double-click opener, and verify mandatory owned closure. Fresh callback bytes/livePID/build association still precede passive host inventory. No host launch, coordinates, private-wire claim or reconstruction/product change follows.
