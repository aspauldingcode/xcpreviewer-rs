# FD attachment ordinals, descriptor permutation and resource alias controls

Actual native BSActionResponse replies now carry owned public xpc_fd objects created from new nonblocking pipes. Each original read descriptor and pipe writer closes before native encoding; expected23-byte content includes the owned fixture's terminating NUL. In the distinct case both factories reuse the same Unix descriptor number, yet received attachment A reads its A content and B reads B content. A reused descriptor integer is therefore not resource identity in this observed control. In the alias case one xpc_fd object appears under two fields: both native Mach descriptors name the same kernel port in this same task; reading A consumes23 bytes and B then observes EOF. Native XPC wire bodies for distinct/alias cases are byte-identical: resource alias identity comes from the attachment table, not an inline FD number.

Native complex message bodies contain uint32 descriptor count2, two12-byte user-space mach_msg_port_descriptor_t records, then a360-byte CPX@/version5 body. SDK header hash and exact public descriptor ABI constants are pinned. FD nodes use tag0xb000 alone, with no inline index/payload; native descriptors are consumed in traversal order. Send descriptors use COPY_SEND19; kernel receive descriptors use PORT_SEND17. All reserved descriptor bytes are zero in these controls. Native sender and receiver body comparison covers every byte after applying only the two public SDK disposition rewrites at offsets14 and26. Observed same-task port names remain equal across each send/receive, but no cross-task/global identity claim follows. Four accepted native/candidate messages compare1,552 complex-body bytes, including descriptor and wire padding. Mach header complex/send-once fields are validated separately. Raw body and port-name captures stay local; public findings contain hashes and equality facts.

Original portable XpcValue gains DescriptorRef(u32), an opaque table ordinal with no OS rights. Ordinary decode_body/encode_body still reject FD tags. Explicit decode_body_with_descriptors consumes the declared table count exactly; encode_body_with_descriptors emits canonical wire plus descriptor_order referencing the caller's original validated table. Counts and output plans are bounded to1024 descriptors. Backend ownership, acquisition, duplication validity, execution and release stay outside this pure codec. Repeated references are a plan requiring an independently valid backend copy policy; the codec creates no capabilities. A new reencode-xpc-attachments CLI reads an extracted body and count, writes a canonical body and reference-order file, and calls no native API.

For the measured payload, canonical key sorting changes FD traversal order and emits plan[1,0]. An owned research dylib copies only SDK-validated original owned COPY_SEND port descriptors in that order, preserving original header/right and substituting the portable wire. Native receiver returns both distinct contents correctly and retains the alias EOF behavior. The same canonical wire with an omitted/identity descriptor permutation is still syntactically accepted but swaps resources and fails the expected-content callback check. This intentional negative proves that valid wire bytes alone do not preserve attachment meaning. Both good and wrong-order controls are retained; no malformed private ABI invocation is used. Aliasing is not inferred from equal ordinal values or wire equality.

Fresh locked replay rebuilds original native helpers and the current portable CLI, captures two native inputs, supplies both to independent Rust corpus tests, and repeats two successful portable/native controls plus the wrong-order failure. Independent Python checks every complex-body byte and expected kernel rewrite; eight mutated byte comparisons reject. All99 core tests pass; four fresh descriptor tests cover actual native corpus, alias/wire separation, table permutation, opt-in/count rejection, repeated references and limits. No private packet fixture is published: tests use original typed models and an explicit local native-corpus environment. An initial compiler rejection of automatic array capture in a block is retained; static fixture storage fixed it before native execution.

They do not implement OS capability execution on portable hosts, prove final Mach/file resource reclamation, cross-process Canvas transport or broad attachment compatibility.
