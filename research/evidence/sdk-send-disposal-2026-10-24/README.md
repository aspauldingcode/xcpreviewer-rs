# SDK late-reply destruction and one local name retirement

An owned canceled XPC reply now has a measured disposal boundary. Its marked late reply reaches libxpc's mach_msg_destroy call with remote disposition MOVE_SEND_ONCE. Immediately before that call, the remote name in this helper's own task is a dead name with one user reference. Immediately after the unchanged SDK destruction call, mach_port_type for that same copied name returns KERN_INVALID_NAME. The normal positive control crosses the observed Mach2 wrapper with the same owned reply marker and returns send-only MACH_MSG_SUCCESS. These are scoped native observations, not global or Canvas resource settlement.

## Discriminating native controls

Normal mode gates the request, keeps the original capture alive, submits the owned marker reply, gets a dictionary callback and observes local capture destruction. The marked88-byte message crosses Mach2 from libdispatch caller offset0x20784 with remote disposition18/MOVE_SEND_ONCE, send-only option and final result0/MACH_MSG_SUCCESS. A later received-message cleanup reaches libxpc's different destroy caller offset0x7ecc with null remote name. It is not the canceled unsent cleanup.

Cancel mode gates the request, requests client cancellation, receives XPC_ERROR_CONNECTION_INVALID and observes its original captured NSObject destruction, then submits/releases the held late peer reply. That marked88-byte message reaches libxpc destroy caller offset0x72cc in phase2 with remote disposition18. There is no marked mach_msg/Mach2 send row in the completed bounded observer ring. The destruction bracket reports type MACH_PORT_TYPE_DEAD_NAME (1048576), successful dead-name refs query with1 user reference, then KERN_INVALID_NAME (15) for that same copied local name after the original call. The observer performs no deallocation itself. This brackets retirement of that name in the owned task; it does not count every global reference, prove underlying kernel-object destruction, prevent later namespace reuse or establish a general concurrent ownership protocol.

A first verifier assertion guessed libdispatch as the destruction caller. The measured image was libxpc, so the assertion failed before cancel findings were updated. The correction uses the actual image/UUID and source callsite; failure is preserved explicitly. Fresh offline analysis resolves the two libxpc callsites' BL/authenticated stubs to exact mach_msg_destroy in the pinned libsystem_kernel image.96 surrounding native bytes independently match LLVM. This correlates actual observed calls with shipped code without inventing the enclosing private function's ABI or complete ownership logic.

The canceled route therefore provides no observed kernel send rejection. In this selected route it supplies a marked local-destruction observation instead. It must not be relabeled the still-open kernel-failed-send cleanup path. Absence is limited to these observed wrappers, completed rows and bounded window; bypassing lower-level/direct paths are not exhaustively instrumented.
