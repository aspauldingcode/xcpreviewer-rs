# Pending native callback lifetime across explicit invalidation

This source-guided R1 experiment tests actual generated scene-action proxy completion lifetime in an owned SDK anonymous listener. It does not substitute helper exit, timeout or a queue barrier for target-operation settlement. The existing retained reply capability is the discriminating resource: withholding it keeps a request genuinely pending instead of accidentally dropping its send-once reply right before the experiment begins.

REA opens the pinned BoardServices ELF SHA c54922ecd497361e02b953006462d9d60b0a31cbf9094788bb730ee5cfc6c4f1. Existing GhidraVibe0.1.1/headless5.14.2 server identity is checked without restart; REA uses Ghidra12.1.2 and closes afterward. BSServiceConnection.invalidate has an88-byte wrapper. Native metadata identifies the lower invalidate entry as an8-byte thunk; REA initially has no procedure there, so LLVM resolves its reason2 branch to the1020-byte state-guarded core. Additional712/80-byte helpers and24-byte selector dispatch are retained. Complete inclusive/noncontiguous ranges total1924 bytes and all opcode bytes independently match ELF through LLVM; thunk8 bytes also match. No private function is called through a guessed prototype. The core snapshots blocks, clears fields and invokes a snapshot outside its lock, but source alone does not identify every block as a pending reply or prove terminal settlement.

Each owned runtime case checks actual loaded BoardServices/BaseBoard UUIDs and exact Objective-C signatures, then uses the established recovered Mach2 observation boundary. A caller-owned heap copy of the completion captures an original OwnedCompletionToken. After native invocation, caller block/token references are released and the inner autoreleasepool drains. The SDK peer signals receipt of the actual independently matching request; the unsent reply object remains retained. Snapshot counts are measured before invalidation, after two explicit owned invalidations and configured-queue synchronization, and after the optional late send. Separate callback/deallocation semaphores are finally awaited with500ms deadlines before peer cancellation. The owned deallocation semaphore is signaled on entry to dealloc, before super dealloc; it observes the zero-strong-reference destruction boundary, not completed allocator reclamation. This particular strong capture is released, but every native resource or external target operation is not thereby settled.

Three discriminating cases repeat in a fresh independently compiled replay:

- Delivered empty reply: callback and token deallocation both occur once before invalidation; callback receives nil.
- Withheld reply: no callback or token deallocation before or after explicit invalidation. Dropping the retained unsent SDK reply object then produces one callback with NSError domain BSServiceConnectionErrorDomain/code3 and one token deallocation. Both events are awaited before canceling the owned peer, separating reply-right abandonment from peer cancellation.
- Late empty reply after invalidation: callback/token remain pending across invalidation; late send produces one nil-error callback and one token deallocation. Thus explicit invalidate/isValid=false is not a terminal pending-completion boundary in this observed route.

All callbacks execute on the configured owned queue in these cases. Each final receipt has one callback, one token mark, one deallocation, and successful callback/deallocation waits. A valid typed request/whole SDK dictionary and actual312-byte request body match the prior frozen native profile in every case, padding included; the two successful empty reply bodies match all20 bytes each. Total976 request/reply bytes compare exactly;66 changed lifetime/identity/callback receipt fields reject. Empty/no-reply traces are distinguished. Error3 is an observed local NSError callback identity following reply-capability abandonment, not a newly inferred CPX error archive or universal cancellation/error code.

Initial finite snapshots alone were insufficient: first receipts saw the callback only later during cleanup and lacked final release evidence. The revised explicit semaphore/token controls supply the missing owned-lifetime observation. Both initial and corrected runs remain local. Queue drains and finite absence observations still do not prove global no-later-effects. The positive late-reply counterexample directly falsifies using explicit invalidation return as completion settlement. Strong token deallocation demonstrates local captured-object release after actual completion/right abandonment only; it does not account for every Mach right, server operation, memory allocator or real Canvas task.
