# Diagnostic failure-report output

The portable file-batch report now writes SerializationErrors.txt using recovered failure ordering and formatting. BatchReport.write_failure_report_into takes an explicit error-description projection and caller-supplied joined UTF-8 byte budget. It skips every callback and sink operation for empty failures, joins descriptions with two LF characters, normalizes literal backslash+n with the existing measured Foundation boundary profile, resolves the report filename in the supplied base and requests an atomic UTF-8 write. Report-write errors are intentionally discarded. Ok(true) means a write was attempted, not that it succeeded. The original collected errors remain intact.

## Portable contract and controls

The description closure explicitly projects native Error string rendering. Arbitrary Rust Display output is not claimed to match Swift Error rendering. The new original limit checks joined UTF-8 length including separators before normalization and before destination resolution/I/O. Descriptions can allocate inside caller code; this is not a bound on caller allocations or native behavior. Literal normalization reuses the existing384-range measured fixed-pattern profile, which is runtime/context scoped rather than a general Unicode algorithm. A combined-string budget failure leaves sink untouched but may have invoked earlier description closures. Neither failure nor success consumes the original errors. No report cleanup, archive directory setup, generated actions or ZIP creation is added.

Five public Foundation controls use CustomStringConvertible errors, the same lazy interpolation/join/replacement expressions and typed String.write(to:atomically:encoding:) in owned temporary directories.
