# Capabilities payload and tolerant outer decoding

The portable ServiceEnvelope now supports capabilities alongside ping/forward. CapabilitiesPayload carries is_running_in_xtp. The outer content is Capabilities(Option<CapabilitiesPayload>): missing or invalid capability data becomes absent capabilities, while malformed root envelope or identifier still rejects. None, Some(false) and Some(true) remain distinct. Encoding absent capabilities produces an empty payload before the shared optional identifier is added; present capabilities emits the exact isRunningInXTP key with a canonical Bool. This is reported peer data, not permission negotiation or ambient runtime detection.

## Original portable implementation

CapabilitiesPayload.decode_dictionary requires the field and accepts the measured primitive Bool projection: Boolean, Integer0/1 or Real0.0/1.0 (including negative zero). Other values reject the standalone payload decoder. ServiceEnvelope catches only this content decoder result and converts its error to absent capabilities. It does not suppress missing/non-dictionary payload, invalid identifier or unsupported outer kind. The existing ping and forward paths remain; ForwardServiceEnvelope remains forward-only. Canonical output drops unknown capability fields and emits Bool rather than preserving NSNumber input representation. No native connection, transport callback, liveness detection, XTP discovery or capability-based action controller is added.
