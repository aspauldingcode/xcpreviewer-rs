# Native owned reply traverses Mach

The earlier owned BSAction serializer/reply control proved endpoint construction and callback delivery, with kernel route explicitly unverified. This experiment supplies the missing same-process kernel observation using an original dylib linked only into a newly compiled owned helper. DYLD interposition wraps the SDK-declared mach_msg and mach_msg_overwrite signatures; no private function ABI is invented, no Apple app is modified or re-signed, and no user process is attached. A direct owned Mach send/receive with message ID0x58504352 independently proves that the hook records actual calls and successful receive data. Hooks record each outer API operation once, cap observations at256 rows and bodies at4096 bytes, use atomic completion admission and suppress nested wrapper duplication. Acceptance requires complete rows and untruncated bodies. One observation epoch is used per helper.

Actual native BSAction decoding supplies its native reply endpoint, and one sendResponse: returns the expected owned string on the configured serial handler queue. All600 post-header bytes are compared, including any body padding; no bytes after the24-byte Mach header are skipped. Public results contain body hashes and sanitized header facts, while complete bodies, endpoint diagnostics and mapped Apple bytes remain local.
