# Follow captured preview updates

Optional Follow sample reads the explicitly selected loopback sample once per second after the previous read finishes, hashes bytes and decodes changed captures through the existing WASM worker. It starts disabled. Each fetch has a five-second abort deadline and a 64 MiB artifact limit. Turning it off, opening a file, manual Open sample or leaving the page cancels polling/pending display work. Epoch checks suppress old reads after stop/restart. Unchanged captures avoid decoding and retain selection; changed captures reset region selection. Fetch/decode failures retain the last good image. Network failure recovery can repaint unchanged good bytes to clear the error status. Background browser timers can be throttled.

Six focused reader/scheduler controls pass from copied source: changed/unchanged bytes, stopped read, restart epoch, failure/recovery/error deduplication, hashing/HTTP/size rejection and active abort. Current viewer/module syntax checks pass. Actual CUA browser controls display opaque and transparent owned native captures, preserve the transparent image on an invalid payload, recover the opaque image, and stop following after manual Open sample. Latest pause feedback is visibly verified. A new actual source-watcher --once capture then feeds the followed sample; all 98,304 browser readback RGBA bytes match its native PNG. Existing WASM converter is pinned/reused, not rebuilt. The browser evidence is retained direct observation, not an unattended replay; verify.py repeats copied-source controls and checks retained receipt/hash consistency.

This is original reconstruction polling policy, not recovered Xcode scheduling or native Canvas lifecycle. Source compilation still happens in the separate Mac producer. No interaction forwarding, provider/session/state migration, final kernel-resource settlement or milestone parity is established. No Rust code/test rerun or user Xcode/simulator process control. Only original code, owned sample/source, sanitized receipts and screenshots are prepared here. Historical publication manifests retain their old hashes; changed UI/docs versions are explicitly superseded in the new pending manifest. No GitHub/commit/push egress attempted while approval is pending.
