## Portable format and bounds

binary_plist_writer emits deterministic bplist00 from the existing Value tree. It handles booleans, signed64-bit integers, finite f64 reals, finite reference-date intervals, data, ASCII/UTF-16BE strings, arrays and string-keyed dictionaries. BTreeMap order is deterministic; object interning and byte-for-byte Foundation serializer identity are not claimed. Negative integers use eight bytes; positive integer width is calculated from u64, preserving values above32 bits on WASM32. Reals and dates retain double bit patterns. Lengths, object references, offsets and trailer fields use checked size arithmetic.

Default hard limits are100,000 objects,64MiB complete output and64 nested levels. Caller limits may reduce these bounds. Dictionary keys count as objects; byte accounting includes header, markers, reference/offset tables and trailer. UTF-8 input strings may shrink when written as UTF-16, so input byte length is not substituted for final encoded size. The writer builds a bounded borrowed node/reference table and validates final size before allocating the output buffer. It does not clone whole input data or trees. Rust allocation failure is not a claimed recoverable transport condition.

Writer output-byte limits and the reader's separate copied/expansion budget are independent: near their ceilings, a valid encoded file can still exceed the reader's expansion budget. The corpus and tests do not claim maximum-size round-trip equivalence.

Null and nonfinite real/date values return explicit profile errors. These are original output-policy restrictions, not assertions that every native parser rejects such values. XML, arbitrary Objective-C objects, UID/set markers, graph identity and full Foundation serialization/coercion policy remain outside this writer's declared contract. The previous reader still accepts its wider input subset. No full Native Canvas parity follows from this bounded output profile.
