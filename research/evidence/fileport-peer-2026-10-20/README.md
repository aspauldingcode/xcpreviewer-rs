# Cross-process file capability and peer-exit boundaries

This independent public-Mach/fileport feasibility control uses new owned fork/exec peers and a random temporary bootstrap rendezvous, reusing the repository's existing SDK rendezvous pattern. No Xcode process, built-in MCP or private bridge is used. The SDK-declared fileport_makeport/fileport_makefd APIs are used directly; no private ABI declaration or guessed Swift call is introduced. It is a generic capability boundary, not evidence of actual Canvas or XPC cross-process encoding.

The child creates a nonblocking pipe, writes31 original bytes including NUL, closes the writer, converts its read descriptor to a fileport and closes the original read descriptor before COPY_SEND transfer. Two independent cases use explicit child-side send-right release followed by normal exit, and _exit(23) with the child-side rights deliberately still live. Parent checks actual audit-trailer sender PID, message geometry/types, waits for that exact child to exit and reaps it before importing descriptors or reading. Thus a timeout or subprocess exit alone is never substituted for target-operation settlement.

In both cases the parent observes one received send reference, imports two file descriptors, reads15 bytes through the first, deallocates its received Mach send right, and verifies that its send-reference entry is absent/zero. The second descriptor then reads the remaining16 bytes and the combined31 bytes match an independent original literal, proving shared read position. Both reach EOF; after explicit close each descriptor gives EBADF via F_GETFD. This separates sender process exit, parent Mach right release and local file descriptor closure. It does not prove final kernel object reclamation or absence of every other possible reference.

A no-send child exits24 without creating a resource. Parent observes the bounded receive timeout, reaps that exact child, then performs a fresh zero-time receive. All three cases require this post-reap queue drain to return MACH_RCV_TIMED_OUT and verify temporary rendezvous removal. This bounds observed owned-process/queue behavior. It is not a universal no-later-effect claim for native Canvas or arbitrary threads. The implementation starts no worker threads and never terminates user processes.

An independent verifier checks every48-byte complex body byte in each successful transfer, including all six reserved descriptor bytes and all32 original payload bytes. The only allowed sender/receiver changes are the nonzero task-local port-name field and SDK COPY_SEND19 to PORT_SEND17 disposition. Port names are not asserted globally equal or resource identities. Count1, descriptor type0 and exact message size are separately checked. Raw send/receive frames and process artifacts stay local; public receipts contain only hashes and equality facts. Eighteen mutated comparisons reject, covering count, invalid name, reserved padding, disposition, type and first/interior/final payload bytes. The original pipe content is compared in full, including its NUL.

Fresh locked replay rebuilds current original C source with SDK headers, runs clean/abrupt/no-send controls under bounded native deadlines and repeats independent verification. An earlier strict compiler rejection of deprecated bootstrap_register is retained; the existing SDK interface is allowed explicitly with the warning visible, without changing privileges. A prior complete three-case run is retained as replication. No product behavior changed, so unrelated portable codec tests were not repeated. Prior sealed reply-attachment evidence and current implementation pins are verified unchanged.

Final fileport reclamation needs a distinct observable proof; local refcount absence and descriptor EBADF are deliberately narrower claims.
