# Automatic typed pilot v2 — producer method and limits

Producer `/root/canvas_evidence_review` read the failed pilot review (35/50, 70%), existing ontology and installed graph-engineering modeling/extraction guidance. This is one bounded producer-rule revision, not a repaired scoring pass over the original predictions. The original fifty and their rejected judgments remain untouched.

Reusable producer `tools/re/canvas_entity_pilot.py` reads the first ten pinned Evidence report nodes in the existing graph and fails closed on source digest mismatch or unsafe relative paths. It extracts one report-title Evidence entity and up to four distinct declarative Claim mentions per report with verbatim Unicode half-open spans and line spans. A bounded grammatical heuristic filters questions, instructions, fragments and selected historical/research framing. It never pads a short report to reach a quota. The actual output contains 50 proposals: ten Evidence and forty Claim entities. Source propositions remain report assertions, not established runtime facts. No relation endpoints, native target IDs or accepted graph edges are emitted.

The reusable role validator rejects singleton identity types when context indicates grouped controls/participants or lacks an explicit selected identity. Event additionally requires an explicit timezone-bearing ISO timestamp and a kind from request/render/completion/cancellation/release. Relative order, requested runloop duration, abort role labels and mutation verbs cannot supply those requirements. This conservative document producer does not attempt runtime roles at all; role validation is a prerequisite for a future structured producer, not evidence that all narrative ambiguity has been solved.

Validation: five unittest cases passed, covering grouped identity rejection despite supplied IDs; timestamp/kind enforcement; Unicode spans and rejection of question/instruction text; digest mismatch and honest short samples; actual pinned report provenance and refusal to set acceptance/precision. Tests validate producer mechanics and regression boundaries, not semantic extraction precision.

The same ten reports and feedback from the failed pilot were used to develop these rules: this is a development sample, never held out. Type coverage is only Evidence and Claim; no Resource/Session/Frame/Event/Target or relation precision is measured. A Claim entity can be correctly extracted even if its asserted proposition is wrong or insufficiently supported. The automatic grammatical filter may still admit descriptive or mixed claims and requires independent semantic review. No assertion is made that all prose clauses are accurate.

Next: a separate serial verifier evaluates all original v2 predictions against source and ontology without repairing them, retains rejected rows in its denominator, and reports the convenience-sample/type-coverage limits. Even a high score here cannot establish global extraction quality, runtime identity precision or relation precision. Additional target/type coverage must be sampled separately. Writes occurred under the repository controller lock. No product/native/UI/compile, Git, delegation, fusion, export or attestation action occurred.
