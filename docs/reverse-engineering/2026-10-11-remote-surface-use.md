# Cross-task use-count and global in-use cleanup

The previous native use-state controls were local to one process. This experiment tests the separate cross-task contribution boundary after both explicit IOSurface Mach resource names have disappeared. The parent retains a CF alias; an audited fork/exec peer retains another CF alias and increments its local use count. Two modes contrast explicit peer decrement and normal exit with SIGKILL of only that owned child. All values are observations on this host, not global reference-count or Canvas completion claims.

In both modes the parent's IOSurfaceGetUseCount is 0 while IOSurfaceIsInUse is true and the peer reports local count 1/global true. Parent increment changes its local count to 1. The peer's clean decrement leaves its local count 0/global true, because the parent still contributes. The parent waits for actual exit 0 in clean mode or signal 9 in abrupt mode, then still observes local count 1/global true. Its own final decrement produces local count 0/global false. Therefore local use count is not a count of remote users, and peer cleanup does not erase the parent's contribution. The abrupt contrast observes no remaining global in-use contribution once the parent decrements; it does not identify the exact kernel teardown instruction or latency.
