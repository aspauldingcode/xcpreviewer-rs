# Snapshot retained failure records and preserve original errors

The finite-expression Rust builder retained the original Error.record by reference. Although the failure getter returned copies, the caller's original Error still exposed that same object: mutation after rejection changed in-memory history while failure.json retained the earlier value. Cyclic/BigInt records made the getter fail serialization. A throwing record getter was evaluated during error handling and replaced the original execution error before retention.

The production failure handler now retrieves and JSON snapshots the selected record inside a separate protected block. Valid serializable data is captured at failure time, independent of caller mutation. Retrieval or serialization failure retains a bounded `record_error` diagnostic and omits the unavailable record; the original Error is always rethrown unchanged. Normal absent records keep the existing minimal shape. This is a JSON snapshot policy; it does not preserve non-JSON types, impose a record byte limit or prove arbitrary serialization methods side-effect-free.
