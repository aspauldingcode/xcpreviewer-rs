# Root-first exit with independent kernel child events

The new owned C watcher registers EVFILT_PROC/NOTE_EXIT/NOTE_EXITSTATUS for two caller-owned PIDs. It validates full birth and executable path before and after registration, then releases the owned fixture's root-exit gate. It sends no signals. Kernel registration and observed status are independent of the supervisor's public snapshot/missing-row conclusion. A four-second watcher deadline and five-second client wait bound this observation; callback blocking and all fixtures remain bounded. The helper is an experiment adapter, not a replacement for general process retirement policy.

Four actual controls observe root exit43 twice and root exit0 twice while an acknowledged, observed setsid child remains alive. The existing supervisor discovers the root's completed wait, then drains that known child. Its SIGTERM handler writes the exact8-byte peer payload and exits42. In each control the watcher receives the root event first, then the child event with kernel exit-status data10752/exit42. Both requested event flags are present. The supervisor's drained/failure=null/tracked2/remaining0 report agrees with its actual root wait and an independently retained proxy completion. Nonzero jobs reject with the original43 error; zero roots resolve. No private abort or hard deadline occurs.

The kernel child exit event confirms termination, not child reaping. The root intentionally does not call waitpid for its child; no child-wait artifact exists. Missing libproc rows are not promoted to reaped status, and NOTE_REAP was not requested. Root0 with child42 is the explicitly chosen owned contrast, not compiler descendant-success semantics. Every peer byte is checked,32 bytes total; all four actual watcher subprocesses wait0.28 resealed faults cover fabricated reaping, event order/status/filter, watcher failures, root/error/receipt accounting, bytes and identity. Four producer slots were consumed once with15-second outer,3-second supervisor and6-second fixture deadlines.

Failed source/compiler diagnostics are retained; the corrected local status variable compiles with -Wall/-Wextra/-Werror. Both source versions are published, the owned executable remains local. The corrected ARM64 watcher and public observer are hash-pinned through the current REA MCP6.2.0; Node/Python filesystem identities match the prior baseline. No Apple binaries/private dumps, user processes or Xcode workspaces were touched. Approved capture bridge remains absent and was not restarted.
