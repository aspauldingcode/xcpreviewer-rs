# Actual Linux alpha execution

The exact anchored alpha renderer and native-array checker now execute on Linux ARM64, using Wasmtime49.0.0 in the existing Colima VM. No module is rebuilt on Linux. The pinned runtime wheel and every extracted file are verified before execution. The cached Linux ARM64 container image is referenced by immutable digest, with pull disabled. No VM is started or stopped.

Three accepted campaigns cover324 fresh renderer instances: nine eighth-step red alpha values, transparent/opaque-blue backgrounds, three tight/padded/unaligned geometries, twice each per campaign. Every complete16,384-byte allocation matches both independent native/model expectations and the frozen macOS V8 output. Each comparison direction covers5,308,416 bytes across the campaigns; these are two comparisons of the same physical allocation extents, not twice as many distinct bytes. Native active comparisons cover29,376 bytes from eight pinned native cases; other values/geometry remain model controls. Thirty-six invalid requests preserve589,824 complete allocation bytes.

The exact native-array checker runs96 controls across campaigns, including72 injected active-pixel/padding/unused-tail mutations. Results match the frozen WasmKit checker rows. Every baseline has zero mismatches and every mutation exactly one. Renderer/checker imports are zero. Runtime limits are131,072 bytes of linear memory and10,000,000 fuel per call. Measured host: Linux6.8.0-100-generic, aarch64, Python3.12.3, Wasmtime49.0.0. This Linux VM runs on Apple hardware; it does not establish independent hardware or Windows coverage.

The owned container is offline, read-only except for its output bind mount, unprivileged at the caller's UID/GID, with dropped capabilities, no-new-privileges, one CPU,256MiB process memory and64 PID limit. Each run has a fresh nonce ownership label and name. Existing container IDs/names are inventoried before and after and preserved. The adapter removes only its own label-verified container if it survives automatic removal; all owned names are absent afterward. User containers and Xcode/simulator processes are preserved.

Verifier controls reject changed anchors before container launch, wrong host/architecture/module/import metadata, changed checker integer types and rehashed active/padding/tail/invalid-buffer corruption. Rehashing a damaged candidate cannot defeat independent expected-byte comparison. The existing shared cleanup tests still reject another owner's label; wheel/file validation is shared with the earlier opaque Linux adapter. Full suite262 tests passes. The final campaign derives byte counts directly from actual comparison extents rather than reporting fixed totals.

Scope: bounded explicit quantized primary-red alpha/blue renderer, native holdouts and declared model-only cases. No Linux source frontend, arbitrary colors/linear profiles, native Canvas wire, Windows/hot reload/cost acceptance follows. F2 and both milestones remain open. Next graph task is a native mixed-color alpha oracle to discriminate export quantization and premultiplication assumptions before broader color compatibility.

Implementation: `tools/re/reloop/linuxalpha.py`, `linux_alpha_runner.py`, shared `linuxwasm.verify_runtime`; sanitized anchors: `research/evidence/linux-alpha-2026-10-10.json`. Raw runtime files, generated modules and native references stay local. No Apple private binary is published.
