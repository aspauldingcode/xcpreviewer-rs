# Strict Rust build receipts

The Rust source builder previously checked selected receipt hashes while accepting additional or weakly typed metadata. It now limits stdout receipt bytes to16KiB, requires exact root/config/source keys, lowercase64-hex identities, finite integer dimensions1..64, three alpha eighths0..8, numeric reverse flag0/1, explicit wasm32-wasip1 target, cache_hit false and the declared finite frontend scope. Arrays, unexpected keys, coercible strings, booleans in numeric flags and nonfinite/range-invalid values are rejected.

The production gate compares source/compiler/toolchain pins, actual module bytes, generated Rust bytes and both actual frozen kernel/template hashes. Those files use the bounded descriptor reader. JSON validation, file reads, receipt checks and external oracle validation remain inside the catch that records failures with the subprocess receipt. Schema validity is not source-semantic or compiler attestation: independent full-byte oracle and WASM ABI/publication gates remain necessary. Future receipt format changes require explicit schema/version migration; unsupported extra metadata is not silently ignored.
