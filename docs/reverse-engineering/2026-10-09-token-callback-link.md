# Cancellation token callback association

The pinned FoundationHost image now has a verified static path from token closure captures to the previously recovered observer dictionary-removal wrappers. This establishes selected native dataflow, not an observed cancellation event or transport release.

The isolated/concurrent partial apply entries `0xc1210` and `0xc12f8` load two captured words from context offset `0x10`, then branch to `0x419cc` and `0x41f10`. Those closures construct three pointers: isolated removal/update `0x42604`/`0xbeecc`, concurrent removal/update `0x428d0`/`0xbeea8`, and common result consumer `0x428fc`. Both closures branch to `0x41f2c`.

The shared helper preserves those pointer arguments, calls the weak-load stub and branches directly to its epilogue if the returned owner is null. The non-null path obtains storage through observed offsets, stores the captured second word at stack offset `0x20`, locks storage offset `0x54`, then invokes the selected update adapter with the removal function and a context rooted at stack offset `0x10`. That makes the saved word available at context offset `0x10`, matching the previously recovered removal-wrapper loads. It unlocks, releases the owner and separately invokes the result consumer. The consumer branches to `0x42648`; its target body remains unverified.

Both update adapters call `0xbeef0`. This helper extracts the high byte of a 16-bit field at state offset `0x40`. Value `1` takes a path that skips the indirect removal callback and writes result marker `1`. The other path retains the callback/context arguments, places the context in `x20`, invokes the callback through `x23`, writes observed storage fields and sets the state/result byte to `0`. These numeric markers are not assigned source enum names. Calls to copy/destroy helpers are visible; their value-witness and ownership effects remain unknown.

The checker requires ten selected entries, compares all 632 captured instruction bytes against independently mapped image bytes, and decodes six ADRP/ADD pointer targets plus thirteen B/BL targets. It additionally verifies the encoded null/state branches and selected register/storage flow. The count includes a dispatch thunk and trailing selected disassembly rows; it does not claim every byte of the full framework, or every possible function path. No padding equality claim applies to these code rows.
