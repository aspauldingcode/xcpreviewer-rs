# Independent Rust primary-layer rendering

The dependency-free canvas-core now renders the measured three-primary contract from a validated configuration. It quantizes each alpha eighth to an8-bit source alpha, composites blue/red/green or green/red/blue with integer source-over rounding after each layer, and writes the complete16384-byte allocation. Visible pixels are premultiplied RGBA; row padding is A5 and unused tail is C3. Width/height1..64 and stride width*4..256 stay explicit. Invalid geometry, stride, alpha or allocation length is rejected before changing any output byte. A finite configuration-to-raw CLI additionally rejects unknown layer order before touching its output file.

Actual macOS/arm64 Rust output matches all84 frozen Fraction allocations (1376256 bytes).80 retain public native scale1 callback-target references (1310720 bytes);4 have independent predictions only. The84 Rust-produced files are separate from predictions and are compared completely, including every padding/tail byte, both layer orders and native extent/alpha holdouts. This replaces no native oracle and infers no display/export color equivalence. The Rust implementation uses integer recurrence while the independent expectation uses Fraction arithmetic. Unsupported colors, arbitrary layer counts, layout, fonts and state remain outside this contract.

Five actual invalid CLI controls (width, height, stride, alpha and order) return diagnostic failure and preserve an existing owned output sentinel. Two new Rust tests verify invalid in-memory output remains unchanged and transparent/opaque controls, including padding, tail and opposite order. Together with retained core tests,7 Rust tests pass. Fresh-context reader verifies every sealed byte, external native/Fraction anchors, all produced allocations and diagnostic/sentinel outcomes. Three resealed false pixel/tail/failure claims reject.
