# Public IOSurface seed versus lock and content bytes

A stable numeric resource ID and retained CF alias do not identify a frame generation. This owned public-API probe independently compares modification seeds and full allocations under read-only access, a no-op write, active/padding/tail edits and exact restoration. SDK source declaration is pinned separately in prediction.json; no Apple header or binary is published.

Both fresh helpers observe initial seed 1 after the controlled producer initialization. Read-only lock/unlock and read-only snapshots return/preserve 1. A write lock that changes no bytes returns lock seed 2; its unlock also returns 2. Subsequent writes return 3,4,5,6 respectively at lock and unlock. This differs from an interpretation that the lock output always supplies the pre-lock GetSeed value: it already supplies the next value on this write route. No GetSeed call was made while locked, so internal update timing versus a returned reserved value remains unresolved. The original prediction is retained; the reader asserts actual observed returns rather than silently replacing the acquisition.

No-op write preserves every byte while changing the seed. Active offset 0, padding offset 68 and unused-tail offset 16,383 are then toggled separately; exact restoration toggles all three back. Final full allocation equals initial bytes despite seed 6 versus initial 1. The public seed therefore is not a byte hash or a unique identifier of byte content. The original and distinct imported CF wrapper agree on all post-unlock seeds while surface ID stays constant. Writer alternates between those wrappers. Read-only snapshots do not further advance the measured seed. Both helpers explicitly remove the resource Mach name before controls, release both CF owners and observe null numeric lookup at a separate 100 ms follow-up.
