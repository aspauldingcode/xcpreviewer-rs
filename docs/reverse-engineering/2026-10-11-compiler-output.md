# Compiler subprocess output bound

Cached-build compiler commands used capture_output with a 30-second deadline but no output size bound. The owned POSIX command boundary now redirects stdout and stderr to temporary regular files, sets a child-only RLIMIT_FSIZE of 4 MiB (or the inherited smaller hard limit), and reads at most limit+1 bytes per stream after waiting. SIGXFSZ or a stream reaching the cap is rejected explicitly. The cap also applies to regular compiler output artifacts written by that child; it is not merely a diagnostic cap. Parent resource limits are unchanged. Invalid nonpositive/noninteger limits fail before launch.

Four actual owned Python emitters independently exercise stdout and stderr in baseline and fixed modes, using an 8,192-byte Z burst and a reduced 4,096-byte test cap. Each emitter explicitly restores default SIGXFSZ behavior. Baseline waits exit 0 and retain all 8,192 bytes. Fixed waits return -25 (SIGXFSZ), retain exactly 4,096 bytes, and reject before accepting a successful compiler result. Child limits are observed as [4096,4096]; parent before/after limits remain [9223372036854775807,9223372036854775807]. Both paths use three-second waits and reap their direct children. This is process output evidence, not actual compilation, executable WASM or native Canvas output.

Independent verification compares all 24,576 diagnostic bytes and rejects seven resealed faults: exit, timeout, reaping, parent/child limits, output and false acceptance. No image or padding is claimed. Build tests inject the compiler-stage boundary explicitly, preserving deterministic fake stage outputs while separating them from OS capture. Historical cache payload evidence remains frozen and its regression now verifies historical semantics rather than requiring current source to equal the older builder.
