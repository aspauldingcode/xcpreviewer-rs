# Native-backed portable alpha reconstruction

A separate owned C renderer now implements explicit red opacity in eighth steps, optionally over opaque blue, using the independently tested quantized-alpha model. It accepts dimensions1…64, height1…64 and byte stride between width×4 and256. Complete storage is16,384 bytes. The existing Swift-like opaque source parser is unchanged; this experiment does not imply alpha expressions compile through it.

The module is generated through saved optimized LLVM IR and linked as import-free WASM. Actual Node V8 execution compares108 fresh instances per campaign:9 alpha steps ×2 background choices ×3 shapes/strides ×2 repeats. Shapes are17×9 with stride68 or80 and3×2 with unaligned stride15. Independent expectations include every active RGBA byte, `0xcd` row padding and `0xa5` unused allocation tail. All54 same-input pairs match. Twelve invalid width/height/stride/alpha/background requests return0 and preserve every allocation byte. The second campaign additionally checks the invalid-request starting allocation against its independent prediction.

Eight declared native cases, including eighth and three-quarter holdouts, are compared to the pinned ImageRenderer seal: zero/quarter/half/full transparent red, quarter/half/eighth/three-quarter red over blue. Each campaign compares16 active frames and9,792 native bytes. Other alpha/background/geometry combinations are model controls, not additional native oracle coverage.

An independent checker uses actual native pixel arrays plus explicit padding/tail expectations. It links the exact saved renderer IR without LTO, rather than recompiling a separate renderer implementation. Both V8 and installed WasmKit execute32 checker cases per campaign. Twenty-four injected mutations target first active pixel, row padding and last unused allocation byte; each returns exactly one mismatch. Every baseline returns zero. WasmKit reports counts from a full16,384-byte internal comparison; its CLI does not export raw pixel dumps.

Across two sealed campaigns,3,538,944 baseline allocation bytes and393,216 invalid-request allocation bytes compare exactly. Native comparisons total19,584 bytes. The renderer and checker WASM files are byte-identical across campaigns. Raw LLVM IR differs in its first two source-path metadata lines; the remaining IR text is identical. This metadata distinction is recorded separately from exact module equality, with no pixel or WASM normalization. Tool binary hashes, Node/V8 versions and IR/module hashes are retained. Full verifier suite256 tests passes.

This is a bounded reconstruction/feasibility result on macOS, using free installed tools. No general color/profile/linear compositing, Canvas wire, browser/Linux/Windows alpha execution, source frontend, hot reload or cost claim follows. F2 and both milestones remain open. Native capture/typed runtime blockers retain their prerequisites. Next graph task is actual browser alpha Canvas2D readback against pinned expectations.
