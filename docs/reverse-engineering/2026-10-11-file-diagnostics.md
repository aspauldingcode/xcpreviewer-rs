# Bounded file-loop diagnostics

SourceFileLoop previously appended every observation/publication/rejection to an unbounded array and exposed no concise diagnostic projection. Repeated editor failures could retain unlimited error strings. It now keeps the latest64 events, counts evicted events (saturating at Number.MAX_SAFE_INTEGER), bounds error text to512 UTF-8 bytes and replaces C0/DEL control characters with spaces. The bounded iteration uses at most1024 input code units and checks complete iteration code points before appending. events() remains a detached copy of the retained window. diagnostics() returns retainedEvents, droppedEvents, latest and lastFailure, with separately detached event objects.

lastFailure means the most recent rejected, invalid-source or unavailable-source event still in the retained window. It becomes null when no such event remains. This is an ephemeral public diagnostic view, not a durable audit ledger, error-path redaction or a substitute for sealed subprocess receipts. Error categories and generation identifiers remain available; arbitrary builder stderr is not added to the public view. Historical frozen evidence retains its prior implementation.
