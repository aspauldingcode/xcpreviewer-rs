# Native zombie visibility versus reaping

An owned public-C fixture creates one acknowledged child in its own session. Before allowing exit, the public libproc observer records the child's live birth-time and executable identity. The controller then authorizes the child to write bytes 0–31 and exit 42. The owning parent calls typed public `waitid(P_PID, child, ..., WEXITED | WNOWAIT)`, reports `CLD_EXITED`/42, and deliberately retains the unreaped child until a second controller acknowledgement. After the intermediate observer snapshot, `waitpid` reaps exactly that child with exit 42. The parent exits 0, followed by one final observer snapshot.

The pinned existing observer returns no row for this known child in both the independently proved unreaped-exited phase and the reaped phase. Live identity was present before exit, including child session ID and ancestry. Every one of the 32 output bytes matches independent expectations. This measured sequence falsifies the assumption that the current observer necessarily emits a full matching `Z` row for a known zombie; it also shows that its empty result alone cannot distinguish this unreaped phase from the post-reap phase.

The source path explains a possible mechanism: the helper skips zombie candidates when `proc_pidpath` cannot supply an executable identity. The experiment does not separately measure the failing path call, so that mechanism remains a source-based explanation rather than a directly measured syscall result. No source or binary from the user-owned backend was changed or published; hashes preserve provenance. The new owned fixture source is published; its local binary stays in research/build. REA server 6.2.0 identity was confirmed separately from the absent private Xcode bridge.

Evidence: `research/evidence/zombie-visibility-2026-10-11`. Six native subprocesses: one bounded compiler, one fixture parent, one finite child and three observer helpers. Compiler deadline 10 seconds, helper deadline 2 seconds, fixture input phases 4 seconds, controller lines/root wait 3 seconds. No signals were sent. The independent reader binds owned IDs, wait statuses, lifetime identity, all bytes, helper hash, phase ordering and budgets; twelve resealed faults must reject. This is one controlled phase comparison, not an A/A population claim.

The conservative final-descendant admission guard remains appropriate: missing rows do not prove retirement. Its matching-zombie success path has source/model evidence but remains unqualified against this native backend. No compiler-wrapper post-root success, physical storage reclaim, arbitrary process quiescence, GPU/Canvas completion or live transport acceptance is claimed. Both milestones remain open.
