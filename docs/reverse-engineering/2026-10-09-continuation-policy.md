# Duplicate completion diagnostics and disassembly acceptance

Six bounded probes follow the pinned Foundation continuation guard's duplicate target. Image identity matches the prior five trusted continuation anchors. The actual chain is guard-supplied target 0x30a00 → intermediate 0x2c988 → shared handler 0x2c99c → private FulfillmentFailureMode.fail at 0x2bc40. The shared handler constructs the diagnostic error and calls policy directly; the initial proposed public OverfulfillHandle.assert handoff is rejected. The public assert entry separately reaches the same policy.

Static policy instructions discriminate the tag at self+0x10. Tag 0 reaches an indirect captured callback; tag 1 enters logging. Other tags test the payload pair and select logging, an assertion helper, or the Swift fatal assertion call followed by a trap. These are instruction-level paths, not executed policy behavior. The continuation default getter copies a constant 16-byte payload and stores tag 2 at output+0x10. No named case is assigned to that representation without separately verifying payload and enum mapping. Merged cancellation-specialization names do not establish cancellation transport or callback ordering.

This narrows the previous guard finding: duplicate completion enters a configurable diagnostic before suppression, and some static paths cannot return normally. A uniform runtime “ignore duplicate and return” claim would exceed the evidence. Native concurrent/reentrant completion and policy execution remain blocked on a safe typed boundary.

## Adapter fixes and failed evidence

The first probe selected three symbol aliases at one address. Its final file contained only a heading because Mach-O symbol selection returned no instructions for an alias; the original symbol-count check nevertheless supported. That sealed result remains unchanged and is explicitly quarantined for body/semantic claims.

The disassembler now requires actual instructions at the requested entry. When symbol selection lacks them, it preserves the failed primary output locally and uses generic llvm-objdump on a bounded interval ending at the next distinct text symbol, capped at 65,536 bytes. Each subprocess has a 30-second deadline. ARM64 instruction words are normalized to the existing exact little-endian byte format, with bit-preservation checks. A second sealed run recovered the body but exposed duplicate alias accounting; its registered unique-count checks failed. The corrected implementation writes one body per address and retains aliases in selection metadata, preventing overwrites. A private-name query miss is also retained; the dependent query uses the instruction-derived exact target.

All six seals verify; corrected body and policy probes support their scoped checks. A local presence audit of 22 disassembly runs and 38 files finds only the already-quarantined heading-only entry; presence does not certify semantics or historical authenticity. The suite passes 119 tests. An initial owned-process cleanup PermissionError is retained; the subsequent authorized full run passes. No user processes were terminated, no private Swift ABI calls made, and no Xcode windows opened. Raw disassembly and aliases remain local; [sanitized evidence](../../research/evidence/continuation-policy-2026-10-09.json) contains sites, outcomes and manifest anchors.
