# Same-clock target poll and supervisor deadline audit

A new owned supervisor wrapper loads the hash-pinned unchanged anchor body and intercepts its existing monotonic clock calls and target Popen polls. Clock results are real original return values passed through unchanged; polls call the original implementation and preserve its return code. A bounded JSONL sidecar records the deadline-base call, target creation, deadline-decision clock values and actual poll results. The wrapper delegates the child invocation to the existing optimized CLI phase wrapper. It adds audit overhead, so measurements qualify these instrumented controls rather than reconstructing historical timing.

Both controls keep the original five-second deadline and complete their owned drain/closure. Case0 records a deadline decision approximately32 milliseconds after the deadline; its first terminal target poll returns -15 approximately117 milliseconds after it, after the deadline decision. The original deadline error remains retained, no frame is admitted and closure has zero workers. Case1 first observes target wait0 approximately41 milliseconds before its deadline, with the final deadline-decision clock also below that deadline. It admits the baseline frame and closes with zero workers. No false deadline is observed in this pair.

The clock is Python's reported mach_absolute_time implementation. Comparisons use values from the same supervisor process only; raw values across cases or CLI marker clocks are not treated as a shared epoch. A terminal poll timestamp follows the actual native wait observation, giving an upper bound on exit time in that same domain. The successful case therefore establishes completion observed before its actual deadline. The earlier zero-wait/deadline case lacks this audit and remains historically ambiguous; its result is not overwritten.
