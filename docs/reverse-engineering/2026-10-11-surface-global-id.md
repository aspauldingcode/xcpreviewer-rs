# Stale global surface ID and retained-right contrast

The prior batch observed a numeric IOSurface ID recur across ownership lifetimes. This probe directly tests the public IOSurfaceLookup(id) boundary with two released controls and one retained Mach-right contrast. All helpers first create an owned 17x9 resource with seed 49 active BGRA formula, a5 row padding and seed 49 unused-tail marker, create one Mach send right, snapshot its full allocation and release the original CF owner. Released controls additionally deallocate that right; held control retains it. A bounded 100 ms lookup occurs before new creations, with temporary returned CF aliases released immediately.

Both released helpers observe the old global ID absent before creation. Their first replacement creation recurs at that numeric ID, and an explicit IOSurfaceLookup(old_id) supplies the replacement's seed 50 active pixels and entire seed 50 unused tail. It does not supply the old frame. The three released-control full snapshots repeat exactly across fresh helper processes. This falsifies a universal claim that a stale numeric global ID identifies the original resource after its ownership lifetime ends.

With the original Mach right retained after CF-owner drop, pre-churn and post-churn global lookups both supply exact old seed 49 image and tail bytes. None of 64 sequential owned replacement creations has the old ID; every replacement has seed 50 bytes. This is a bounded observed contrast, not a universal uniqueness or arbitrary recycling guarantee. Replacement candidate IDs themselves recur across their short lifetimes; they are not version numbers.
