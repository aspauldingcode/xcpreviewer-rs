# Correlated Rustc kernel exit and parent wait

A new signal-free single-process watcher validates full public birth identity and executable path before and after NOTE_EXIT/NOTE_EXITSTATUS registration, emits an acknowledged registration record, then observes one kernel exit with a four-second deadline. This removes the two-process/root-exit gate requirement from the previous watcher and supplies an adapter usable for actual compiler descendant correlation.

Two owned actual Rustc cancellation controls now wait for that independent registration acknowledgement before the direct parent sends SIGTERM. The parent verifies the known Popen child's PID, parent, new session group and full libproc identity twice. Both actual parent waits return -15 and both independent kernel raw statuses are15, decoded separately with Python wait macros as SIGTERM. Both watchers actually return0 with empty diagnostics. Every byte of the two deterministic Rust source inputs and empty output streams is independently compared; no final metadata output exists. The observed executable is actual pinned Rustc; its internal parsing/code-generation phase is not observed.

Native acquisition uses two slots once, with bounded live observation, parent wait and watcher deadlines. Owned failures remain retained; this acquisition has no producer failure.
