# Per-builder stage allocation budget

Added a `stageLimit` option to `RustSourceBuilder`, default64 and validated range1–256. Each newly allocated stage consumes the instance budget; `build.budget()` reports the limit and created count. Already-cancelled jobs reject before the budget check/allocation and consume no stage. Exhaustion returns `Rust build stage budget exhausted` before directory creation or execution handoff. Failed active stages remain charged and retained. No cleanup, deletion or global root scan is introduced.

Evidence: `research/evidence/build-stage-budget-2026-10-11`. Actual JS/filesystem before/after controls use a synthetic failed execution boundary and a configured limit2. The previous builder ignores that option and stages three jobs; the fixed builder stages two and rejects the third. Repeated exhausted requests add no stage or handoff. A pre-cancelled request leaves the counter0. Invalid limits reject before root creation. History limit1 retains newest failure metadata while all five actual failure artifacts remain on disk.

Five retained source copies compare completely to a hash-pinned202byte fixture,1010bytes. Two controlled stand-ins for unrelated root contents compare all twelve sentinel bytes unchanged. Twelve resealed faults reject count, charge, handoff, retry, failure/source preservation and overstated scope. The quota is per builder instance and counts newly allocated stages. It does not bound bytes written inside a stage, count prior root contents, survive instance recreation, or limit all work sharing a filesystem root. Those remain hardening acceptance gaps.
