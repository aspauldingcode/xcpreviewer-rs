# Independent Quartz producer and public color contrast

An owned CGContext producer now draws the same14 mixed-color/alpha inputs used by the native ImageRenderer oracle. The context is17×9,8-bit/32-bit explicit big-endian premultiplied RGBA, sRGB, stride80. Active pixels start transparent zero; all12 padding bytes per row start0xa5. Every720-byte allocation compares against predeclared rational/float32 models, measured ImageRenderer pixels with independently declared sentinel padding, and a fresh-process repeat. The native-derived comparison is a producer relation, not an independent source formula.

Three supported native campaigns produce280 allocations,201,600 complete bytes,30,240 padding bytes and140 equal repeat pairs. The first contrasts original Double components with public NSColor sRGB components. The second adds direct public Color.cgColor and NSColor.cgColor inputs. The third changes only CGContext blend mode from copy to normal over the same transparent active pixels. All padding remains0xa5; no allocation byte is excluded from comparison.

Original Double draws match the independent rational half-up model in all28 executions per campaign. Rational ties-to-even matches20/28. Two other declared float32 formulas also match28/28 for these inputs, so these cases do not uniquely identify a numeric implementation. Public-component and direct public-color draws match rational half-up20/28 and ties-to-even22/28; none of the declared formulas matches all those cases.

Every source route matches pinned ImageRenderer raw pixels in only18/28 executions. Cases3,10,11,12,13 differ for every route: the original three-quarter blue tie plus all four subsequent holdouts. Original Double versus public components differ in four cases. Within the four-input campaigns, reconstructed public NSColor components, Color.cgColor and NSColor.cgColor produce exactly equal complete allocations. Recorded public Color.cgColor uses extended sRGB and has some component values differing from converted NSColor sRGB. Equal drawn output does not establish equal input objects, source profiles or renderer-internal conversion.

A separate sealed experiment verifies112 externally anchored copy-versus-normal allocation pairs:80,640 bytes compare exactly. These are reused producer bytes, not additional acquisitions. Therefore changing only this blend mode does not explain the native ImageRenderer counterexamples in this zero-background fixture. This does not prove that blend mode never matters or identify ImageRenderer's internal graphics operations.

Failures are retained. The initial compiler run rejected Double-pointer components where CGColor requires CGFloat; explicit CGFloat conversion corrected the harness without changing predictions. An initial four-input campaign accidentally executed four repeats while checking only two input variants' repeat pairs. Its224 allocations remain sealed/inconclusive and are excluded from the supported totals. The corrected adapter separates two processes from four input variants and checks all56 repeat pairs. A controlled fake acquisition test damages the last variant's final padding byte and fails both repeat/padding predicates; fake acquisition remains test data, never native evidence.

Seven new tests bring the suite to278. They check independent predictions and full native-derived extents, strict metadata and mode isolation, changed-anchor rejection before compilation, first/last pixels and padding, truncated/extended data, all public-input repeat accounting and the last padding byte of sealed blend comparison. All six seals verify. Native compilation/captures retain60s/10s deadlines, exclusive controller lock and owned process cleanup; comparison-only execution is bounded30s. No Xcode workspace opens. Native identity remains macOS26.5.1/25F80 ARM64, Apple Swift6.3.3.
