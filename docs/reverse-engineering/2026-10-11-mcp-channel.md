# Bounded MCP stream and cancellation controls (2026-10-11)

serveMcp adds UTF-8/newline framing around PreviewMcp, serialized operation dispatch, an eight-item pending queue, bounded output/backpressure, EOF teardown and optional notification cancellation. Unlike the custom preview NDJSON channel, multiple MCP messages in one chunk are parsed and dispatched in order. Invalid JSON produces a JSON-RPC parse error and subsequent valid requests continue. A split multibyte client name survives bytewise input. Notifications produce no replies.

Cancellation is an owned reconstruction policy. Cancelling the active tools/call closes the owned preview session, awaits its cooperative work and suppresses its pending response. This ends that preview session rather than preserving it for later builds. Cancelling a queued request removes it and retains its used ID, preventing later reuse. Unknown, malformed, completed and initialize cancellation are ignored. Already-started output writes are not undone. EOF removes queued messages, suppresses pending request responses and closes the session. Counters measure accepted JSON messages, response write attempts and responses suppressed before writing; they are not native resource counts.

Limits:4096-byte line,65536-byte input chunk,32768-byte response, eight queued items plus one active item,500–10000ms channel lifetime and50–1000ms output-drain timeout. Bounds are owned policy, not universal MCP requirements. The lifetime timer initiates close; hard termination of an arbitrary uncooperative session is not guaranteed. A real process wrapper still needs an outer deadline. A caller must give one handler/session exclusively to one channel. Malformed raw UTF-8, overlarge lines/chunks and queue overflow close the channel; no unbounded parser/output buffer is introduced.

Predictions and observations: ten owned stream controls cover normal negotiation/discovery/frame, parse-error recovery, active and queued cancellation, pending EOF, queue overflow, size, invalid UTF-8, input chunk bound, idle deadline, undrained output and scalar JSON plus EOF. All close their fake session with no pending operation. Unknown cancellation does not close the blocked operation; matched cancellation does. The queued cancelled ID remains unavailable. Scalar JSON yields an invalid-request reply before EOF, so no claim is made that EOF retracts an already-written reply. Input/output are owned PassThrough/Writable controls in a bounded Node subprocess, not an actual external stdio client or real compiler session.

Independent Python verification rehashes the parent handler evidence and Node executable identity, checks all16384 synthetic allocation bytes against an arithmetic expectation, and runs two fresh Node stream replays. Three resealed mutations falsify cancellation suppression, EOF cleanup and an allocation byte; all reject. Clean candidate archive:81 Python plus7 Rust tests.
