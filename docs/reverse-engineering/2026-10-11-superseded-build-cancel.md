# Cooperative cancellation of superseded source builds

`SourceFileLoop` invalidated old generation tickets when a newer observation arrived, but left the obsolete builder running until it independently returned. A cooperative delayed builder exposes the distinction: before the fix, a new valid source, invalid source, source deletion and forced refresh all leave its AbortSignal untouched. The old builder must be manually released before the loop can progress. Stale-ticket rejection prevents publication, but does not cancel that obsolete work.

The loop now aborts its current cooperative builder when a changed or forced observation supersedes it, before deciding whether the latest source can be built. This uses the existing builder contract: the builder must honor AbortSignal and settle on abort. It preserves latest-ticket validation and last accepted frame semantics. It does not claim cancellation of an arbitrary compiler process tree or a builder that ignores AbortSignal; reentrant user abort callbacks and native Canvas cancellation remain separate qualification work.

Evidence: `research/evidence/superseded-build-cancel-2026-10-11`. Eight before/after sequences exercise valid replacement, invalid bytes, missing source and forced same-source refresh. Fixed sequences cancel before any manual release. Valid/refresh requests publish only generation3; invalid/missing requests retain generation1's accepted frame. Obsolete generation2 never publishes. All final loop statuses show zero live workers, no timers, no build in progress and closed lifecycle.

The control executes actual V8 WASM using three pinned prebuilt source-revision fixtures; it does not compile fresh code.
